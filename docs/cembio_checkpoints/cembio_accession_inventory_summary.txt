Interpretation
--------------
The current protein identifiers are not direct UniProt accessions. They mostly correspond to ENA, GenBank, RefSeq, assembly, or contig-derived protein identifiers. Therefore, the old AlphaFold DB workflow that expects UniProt accessions should not be run directly on these FASTA files.

Metadata needed next
--------------------
To connect these proteins to functional annotation or AlphaFold DB structures, we need additional metadata if available. Useful files would include GFF, GBFF, GBK, feature_table, protein_table, Prokka/Bakta outputs, NCBI annotation reports, or any file containing protein_id, locus_tag, product, gene, organism strain, assembly accession, or UniProt cross-references.

Decision
--------
Before structural analysis, the next step is metadata/ID normalization. If external annotation files are available, they should be inspected and merged with the master table. If not, we should build a minimal metadata table from filenames and accession patterns, then choose an alternative annotation strategy.
